1. 多源融合：覆盖课题明确的3类数据源（电子健康档案、体检数据、问卷数据），字段统一规范，解决“接口不统一、质量参差不齐”的关键问题；

2. 适配建模：字段类型、取值规范贴合Spark MLlib特征工程需求（如数值型、类别型字段区分清晰），便于后续特征提取、交叉组合；

## 三、数据集维护要点（贴合课题数据治理需求）

结合课题“数据整合与治理体系构建”“数据湖架构”要求，数据集维护需重点关注以下4点，确保数据质量、时效性和安全性：

1. 数据标准化维护：所有字段需按统一规范录入（如性别、饮食偏好的类别编码统一），数值型字段需校验单位一致性（如血压单位统一为mmHg），解决课题“数据质量参差不齐”的问题；

2. 数据清洗与脱敏维护：定期清理重复数据、缺失数据（如用中位数填充血压缺失值），对敏感字段（身份证、电话）进行脱敏处理，符合医疗隐私安全要求，贴合课题数据治理核心需求；

3. 增量更新维护：依托数据湖架构，定期同步电子健康档案、体检数据、问卷数据的新增/更新内容，更新update_time字段，确保数据时效性，贴合课题“支持增量更新”的要求；

4. 数据校验维护：定期校验字段关联性（如BMI计算是否正确、年龄与出生日期是否匹配），避免数据错误，确保数据集高质量，为Spark MLlib模型训练提供可靠支撑。
